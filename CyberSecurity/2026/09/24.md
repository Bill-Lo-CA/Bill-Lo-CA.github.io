# 2026-09-24｜每日資安學習

## 1/4｜每日資安小知識：Memory Forensics——為什麼「看記憶體」能抓到磁碟上看不到的攻擊？

Memory Forensics（記憶體鑑識）最大的價值，是它觀察的是「系統正在執行時的真實狀態」，而不是只看寫在磁碟上的檔案。

很多現代攻擊會刻意降低 disk footprint（磁碟落地痕跡）：

- PowerShell in-memory execution
- reflective loading
- process injection
- credential material 存在於記憶體
- 已刪除但仍被 process 開啟的檔案
- decrypted configuration
- network socket state
- malware unpack 後的 payload

所以一台主機即使磁碟上沒有明顯惡意檔案，RAM (Random Access Memory，隨機存取記憶體) 裡仍可能保留攻擊者正在使用的 code、process、handle、credential material 與 connection context。

---

### 1. 核心概念：Memory image 到底是什麼？

作業系統看到的「記憶體」不是單純一大片連續 RAM。

現代 OS (Operating System，作業系統) 使用 virtual memory（虛擬記憶體）。每個 process 都有自己的 virtual address space，再由 kernel 透過 page table 對應到：

- physical memory page
- swap / pagefile
- mapped file
- shared memory

因此 memory forensics 真正要做的，是從 physical memory dump 或 crash dump 中重建：

- kernel structures
- process list
- thread
- Virtual Address Descriptor
- loaded module
- handle table
- token
- network endpoint
- registry hive
- command history
- executable memory region

也就是把「RAM 裡散落的 page」重新解釋成 OS 原本理解的物件。

---

### 2. 為什麼工具需要知道 kernel 結構？

假設 memory dump 裡有數 GB binary data。

單純搜尋字串只能找到零碎 fragment，無法可靠回答：

- 哪個 process 擁有這段記憶體？
- PID (Process Identifier，程序識別碼) 是多少？
- parent process 是誰？
- 這個 socket 屬於哪個 process？
- 這段 executable memory 是 image-backed 還是 anonymous？
- 某個 access token 有哪些 privilege？

Memory forensic framework，例如 Volatility，會理解特定 OS build 的 kernel data structure。

Windows 內部 process 常由 EPROCESS structure 表示，其中可連到：

- process ID
- process name
- thread list
- token
- virtual address space
- handle table

因此 forensic tool 並不是「神奇地猜到 process」，而是：

**解析 kernel data structure → follow pointer → 重建 OS state。**

這也是為什麼 OS version / build / symbol 解析非常重要。

---

### 3. Virtual memory 為什麼讓鑑識變難？

CPU (Central Processing Unit，中央處理器) 執行 process 時使用 virtual address。

假設 process 中有 virtual address：

```text
0x7ff612340000
```

這不代表 physical RAM 中真的存在同樣 offset。

Page table 會把 virtual page 映射到 physical page frame。

因此 memory tool 若要 dump 某 process 的記憶體，需要：

1. 找 process 的 page-table root。
2. 解析多層 page table。
3. 把 virtual address 轉成 physical offset。
4. 從 dump 中讀出實際 page。

x86-64 Windows 使用多層 page table，常見概念包括：

- PML4 (Page Map Level 4)
- PDPT (Page Directory Pointer Table)
- PD (Page Directory)
- PT (Page Table)
- PTE (Page Table Entry)

你不需要每天手算 address translation，但要理解：

**Process memory view 是 OS + MMU (Memory Management Unit，記憶體管理單元) 建立出的虛擬視圖，不等同於 dump file 中的物理排列。**

---

### 4. Process listing 為什麼有很多方法？

Memory forensic 工具常同時提供多種 process discovery 方法。

原因是 attacker 可以做 DKOM (Direct Kernel Object Manipulation，直接核心物件操控)。

例如 Windows 常規 process list 依 kernel linked list 維護。

Rootkit 若把自己的 EPROCESS 從 active process linked list unlink，普通 enumeration 可能看不到它。

但它的 object 仍可能：

- 留在 memory pool
- 擁有 thread
- 擁有 handle
- 擁有 page table
- 有 network connection

因此 forensic 工具會有不同策略，例如：

- 正常走 kernel process list
- scan memory pool 找 process signature
- cross-view comparison

如果：

```text
pslist 看不到
psscan 找得到
```

就值得深入調查。

但這並不自動等於 rootkit，因為 exited process 的殘留 object 也可能被 scan 到。

---

### 5. Process Injection 在記憶體中會留下什麼？

Process injection 是非常適合 memory forensics 的案例。

攻擊者可能：

1. 開啟合法 process。
2. 配置一塊新 memory。
3. 寫入 shellcode 或 Portable Executable。
4. 改 page protection 為 executable。
5. 建立 remote thread 或 hijack existing execution flow。

常見 API (Application Programming Interface，應用程式介面) chain 可能包含：

- OpenProcess
- VirtualAllocEx
- WriteProcessMemory
- VirtualProtectEx
- CreateRemoteThread

但真正的鑑識重點不是死背 API，而是看 memory region 的性質。

例如正常 executable module 通常是：

- file-backed
- 有 PE (Portable Executable，可攜式執行檔) mapping
- 位於合理 module list
- memory protection 符合 section 特性

可疑 injected region 可能是：

- Private memory
- executable
- 沒對應正常 file mapping
- region 內存在 PE header 或 shellcode
- thread instruction pointer 落在 anonymous executable region

這是很多工具做 malfind 類檢查的基本 mental model。

---

### 6. RWX 為什麼可疑，但不能單獨當 IOC？

RWX 代表 page 同時具有：

- Read
- Write
- Execute

攻擊者很喜歡 RWX，因為 payload 可以寫入後直接執行。

但 legit software 也可能使用 RWX，例如：

- JIT (Just-In-Time，即時編譯)
- browser engine
- .NET runtime
- Java Virtual Machine
- game anti-cheat
- security product
- packer

因此 detection 不應該是：

**看到 RWX → malware**

而應該是：

**RWX + process reputation + region type + thread start address + PE artifact + parent/child context + network behavior**

這就是典型 forensic correlation。

---

### 7. Reflective Loading 為什麼磁碟掃描容易漏？

正常 DLL (Dynamic-Link Library，動態連結程式庫) loading 通常由 Windows loader：

- 從 file system 讀 DLL
- mapping section
- resolve import
- relocation
- 建立 loader metadata

Reflective DLL loading 則讓 attacker 自己在 memory 裡做 loader 工作。

Payload 可以：

1. 已經存在於 memory。
2. 自己找到 kernel32 / ntdll function。
3. allocate region。
4. copy section。
5. resolve import。
6. apply relocation。
7. jump 到 entry point。

結果：

- DLL 可能根本沒有正常磁碟檔案。
- module list 可能沒有完整 loader entry。
- 但 process memory 中存在完整或部分 PE structure。

所以 memory forensic 常會做：

- scan PE header
- 比較 VAD (Virtual Address Descriptor，虛擬位址描述符)
- module list cross-check
- executable private region analysis

---

### 8. VAD 為什麼重要？

Windows 使用 VAD 管理 process virtual memory range。

每個 region 會描述：

- virtual address range
- protection
- mapping type
- backing source

對 analyst 來說，VAD tree 可以回答：

「這段 memory 為什麼存在？」

例如：

```text
0x000001d000000000 - 0x000001d000020000
Private
PAGE_EXECUTE_READWRITE
No file backing
```

比單純看到一串 bytes 有意義得多。

如果該 region 裡再看到：

- MZ header
- PE structure
- suspicious strings
- C2 domain
- thread start address

就能建立很強的 injection evidence chain。

---

### 9. Credential material 為什麼會在 RAM？

很多 authentication mechanism 需要在 session 存活期間保留 credential-derived material。

Windows LSASS (Local Security Authority Subsystem Service，本機安全性授權子系統服務) 會管理：

- logon session
- authentication package
- token-related security context
- Kerberos material
- NTLM (NT LAN Manager) authentication material

這也是為什麼 credential dumping 常把 LSASS 當成高價值目標。

重要的是：

**不是所有 memory 中看到的 credential artifact 都是 plaintext password。**

可能看到的包括：

- NT hash
- Kerberos ticket
- key material
- session structure
- cached authentication material

現代 Windows 版本、Credential Guard、Protected Process Light 等機制會改變 attacker 與 forensic analyst 能看到的內容。

---

### 10. Network Forensics 與 Memory Forensics 怎麼互補？

PCAP (Packet Capture，封包擷取) 告訴你「網路上流過什麼」。

Memory dump 則可能告訴你：

- 哪個 process 擁有 socket
- local / remote endpoint
- connection state
- process image
- command line
- memory-resident C2 config

例如 firewall 看到：

```text
10.0.10.25 -> 185.XX.XX.40:443
```

Memory forensic 可能進一步回答：

```text
PID 4820
process: svchost.exe
parent: winword.exe
private executable VAD
embedded domain: api-sync-example[.]com
```

這樣「一條 network IOC」才被串成完整 execution story。

---

### 11. 具體 SOC/IR 情境

假設 SOC 收到 EDR alert：

```text
WINWORD.EXE -> powershell.exe
powershell.exe -> rundll32.exe
rundll32.exe outbound HTTPS
```

但 endpoint containment 後，磁碟掃描沒有找到 malicious DLL。

如果有 memory capture，可以：

1. 列 process tree。
2. 找 rundll32 的 loaded module。
3. 檢查 private executable region。
4. 找 thread start address。
5. dump 可疑 memory region。
6. 對 dump 做 strings / YARA。
7. 找 network socket owner。
8. 搜尋 decrypted C2 configuration。
9. 比較 PE image 是否存在於 disk。
10. 將時間線與 EDR / proxy / DNS log 對齊。

這種情況下，memory dump 可能是唯一能還原真正 payload 的來源。

---

### 12. Detection / Investigation Telemetry

Memory forensics 通常不是第一線 continuous detection telemetry，而是 incident investigation artifact。

最有價值的來源包括：

- full memory dump
- kernel crash dump
- hibernation file
- pagefile / swap
- EDR memory telemetry
- process dump
- minidump

調查時常看：

- process / parent-child relationship
- command line
- thread
- injected memory
- loaded / unlinked module
- token
- handle
- network endpoint
- registry artifact
- console / command history
- credential-related structure

---

### 13. False Positive 與 limitation

Memory forensics 非常強，但也不是萬能。

#### Snapshot timing

Memory capture 是一個時間點。

如果 malware 已退出、memory 已被 reuse，artifact 可能消失。

#### Acquisition changes state

你執行 memory acquisition tool，本身就會：

- 建 process
- allocate memory
- 讀 kernel
- 產生 I/O

因此 acquisition 並不是完全零干擾。

#### Huge data volume

16 GB、64 GB、128 GB RAM 的 image 很常見。

Analyst 必須有 hypothesis，不然很容易陷入「什麼都掃」的資料海洋。

#### Kernel version dependency

OS build 或 symbol 不正確，解析結果可能錯。

#### Encryption / enclave / virtualization

某些秘密可能存在於：
- hardware-backed enclave
- virtual machine
- protected process
- encrypted memory region

一般 memory dump 未必能完整取得。

---

### 14. 防禦上的 trade-off

企業若想讓 memory forensics 更有價值，需要在 incident 前準備：

- memory acquisition procedure
- forensic storage capacity
- evidence handling
- endpoint privilege
- response tooling
- legal / privacy policy

但 RAM 很可能包含極敏感資料：

- credential material
- document content
- browser session
- encryption key
- PII (Personally Identifiable Information，個人可識別資訊)

所以「多收證據」與「減少敏感資料暴露」本身就是 trade-off。

不是每次事件都應無條件 dump 128 GB memory；應根據 incident severity 與 investigation question 決定。

---

### 15. 與其他已學概念的連結

#### 與 EDR

EDR 告訴你「當時 sensor 看到了什麼」。

Memory forensics 則能在事後直接重建 endpoint runtime state。

EDR coverage 很強，但如果 sensor 沒有特定 telemetry，memory dump 有機會補洞。

#### 與 DFIR Order of Volatility

RAM 比磁碟更 volatile。

因此若關機會破壞重要 evidence，在安全與程序允許時，memory acquisition 應在 disk imaging 前優先考量。

#### 與 Secure Coding

Memory corruption exploit 與 memory forensics 也會交會。

例如 shellcode、ROP (Return-Oriented Programming，返回導向程式設計)、heap artifact 都可能在 memory 中留下痕跡。

#### 與 Windows Internals

理解 process、VAD、token、handle、PE loader、virtual memory，會直接提升 memory forensics 能力。

也就是說：

**Windows Internals 並不是和 DFIR 分開的領域；它其實就是你解讀 forensic artifact 的語言。**

---

### 今天應該記住

1. **Memory forensics 的價值，在於它能看到 process、socket、token、injected code 與 decrypted payload 等 runtime state。**
2. **Virtual address 不等於 physical offset；forensic tool 必須靠 page table 與 kernel structure 重建 process view。**
3. **Private + executable + no file backing 很可疑，但 RWX 本身不能直接等於 malware。**
4. **Process injection / reflective loading 最重要的 evidence 常在 VAD、thread start address、memory protection 與 module cross-view。**
5. **Memory image 是高價值但高敏感度 artifact；acquisition timing、privacy、storage 與 OS build 都會影響調查。**

## 2/4｜CySA：事件中的補償性控制

### English original

An incident response team is working with law enforcement to investigate an active web server compromise. The decision has been made to keep the server running and to implement compensating controls for a period of time. The web service must be accessible from the internet via the reverse proxy and must connect to a database server. Which of the following compensating controls will help contain the adversary while meeting the other requirements? **(Choose two).**

A. Drop the tables on the database server to prevent data exfiltration.  
B. Deploy EDR on the web server and the database server to reduce the adversary’s capabilities.  
C. Stop the httpd service on the web server so that the adversary can not use web exploits.  
D. Use microsegmentation to restrict connectivity to/from the web and database servers.  
E. Comment out the HTTP account in the /etc/passwd file of the web server.  
F. Move the database from the database server to the web server.

### 中文完整翻譯

事件回應團隊正與執法單位合作，調查一台仍在遭入侵的 Web Server。團隊已決定暫時維持伺服器運作，並在一段時間內實施 compensating controls（補償性控制）。該 Web service 必須能透過 reverse proxy 從 Internet 存取，同時也必須能連線至 database server。下列哪些補償性控制可以在滿足這些要求的同時限制攻擊者？**（選兩項）**

A. 刪除 database server 上的 tables，以防止資料外洩。  
B. 在 Web server 與 database server 部署 EDR (Endpoint Detection and Response，端點偵測與回應)，以降低攻擊者的能力。  
C. 停止 Web server 上的 httpd service，使攻擊者無法利用 Web exploit。  
D. 使用 microsegmentation（微分段）限制 Web server 與 database server 的進出連線。  
E. 將 Web server 的 /etc/passwd 中 HTTP account 註解掉。  
F. 將 database 從 database server 移到 Web server。

---

### 答案與解析

**正確答案：B、D**

#### 為什麼 B 正確

EDR 可以提高 endpoint visibility 與 containment 能力，例如：

- process monitoring
- behavioral detection
- isolation / blocking
- malicious child process detection
- suspicious persistence detection

題目限制「server 必須繼續運作」，所以不能直接 shutdown 或完全隔離。

EDR 屬於典型的補償性控制：在暫時無法移除 compromised system 的情況下，加強偵測與限制能力。

#### 為什麼 D 正確

Microsegmentation 的核心是：

**只允許業務真的需要的 network path，其餘 lateral movement path 全部縮小。**

此題已經明確指出必要 traffic：

- Internet → reverse proxy → web server
- web server → database server

因此可以把其他 east-west / outbound connectivity 嚴格限制。

即使 adversary 還在 web server 上，也能降低：

- lateral movement
- C2 egress
- secondary system access
- unnecessary database access path

#### 其他選項為什麼不對

**A. Drop the tables on the database server**  
這會破壞 production data，本質上不是合理 containment，而且直接違反維持服務的業務需求。

**C. Stop the httpd service**  
Web service 必須維持 Internet 可存取，因此不能停掉主要 Web daemon。

**E. Comment out the HTTP account in /etc/passwd**  
單純註解 account 不等於可靠 containment，而且可能直接讓 service 無法運作。攻擊者若已有其他 persistence，也不會因此被有效限制。

**F. Move the database to the web server**  
這反而減少 segmentation，把 application 與 data 放在同一 compromised host，會增加 blast radius。

#### CySA / 實務概念

Compensating control 是在「理想控制暫時不能做」時，使用其他控制降低同類風險。

本題 ideal response 可能是立即隔離、重建 server，但法律調查與 operational requirement 要求 server 保持上線，因此用：

- endpoint monitoring / response
- network segmentation

來降低 adversary freedom。

#### SOC / IR 記憶點

**Containment 不等於一定要斷網。真正目標是縮小 adversary 能做的事情與可到達的範圍。**

## 3/4｜CySA：程式中的敏感資訊判斷

### English original

A SOC analyst identifies the following content while examining the output of a debugger command over a client-server application:

```text
getConnection(database01,"alpha" ,"AxTv.127GdCx94GTd");
```

Which of the following is the most likely vulnerability in this system?

A. Lack of input validation  
B. SQL injection  
C. Hard-coded credential  
D. Buffer overflow

### 中文完整翻譯

一名 SOC (Security Operations Center，安全營運中心) analyst 在檢查 client-server application 的 debugger command output 時，發現以下內容：

```text
getConnection(database01,"alpha" ,"AxTv.127GdCx94GTd");
```

下列哪一項最可能是此系統中的漏洞？

A. 缺乏輸入驗證  
B. SQL injection（SQL 注入）  
C. Hard-coded credential（硬編碼憑證）  
D. Buffer overflow（緩衝區溢位）

---

### 答案與解析

**正確答案：C. Hard-coded credential**

#### 為什麼正確

這段程式碼直接把 database connection 所需的 credential material 寫在程式邏輯中：

```text
database01
alpha
AxTv.127GdCx94GTd
```

其中 `alpha` 很可能是 username，而後面的字串很像 password / secret。

只要 analyst、developer、attacker 能：

- 取得 binary
- 讀 source code
- dump memory
- attach debugger
- decompile application

就可能取得 credential。

這就是 hard-coded secret 的典型問題。

#### 其他選項為什麼不對

**A. Lack of input validation**  
題目沒有顯示 user-controlled input 被直接處理，也沒有輸入 validation context。

**B. SQL injection**  
SQL injection 需要不受信任輸入進入 SQL query context。這裡只是 database connection function，沒有看到 SQL query 拼接。

**D. Buffer overflow**  
沒有 fixed-size buffer、unsafe memory copy、length handling 等證據。

#### 背後需要掌握的 CySA / 實務概念

Hard-coded credentials 可能出現在：

- source code
- configuration file
- script
- container image
- mobile app
- compiled binary
- CI/CD (Continuous Integration / Continuous Delivery，持續整合／持續交付) pipeline
- Infrastructure as Code

即使 binary 已 compile，string literal 往往仍能透過：

- strings
- debugger
- reverse engineering
- memory dump

被找到。

更好的設計包括：

- secret manager
- environment / workload identity
- short-lived token
- managed identity
- rotation

但 environment variable 也不代表秘密絕對安全；很多 process / crash dump / diagnostic system 仍可能暴露它。

#### SOC / IR 記憶點

**Secret 不應該和 application artifact 綁死在一起。只要 credential 跟 binary 一起部署，就要假設拿到 binary 的人有機會把它抽出來。**

## 4/4｜CySA：跨系統事件關聯判斷

### English original

An analyst is examining events in multiple systems but is having difficulty correlating data points. Which of the following is most likely the issue with the system?

A. Access rights  
B. Network segmentation  
C. Time synchronization  
D. Invalid playbook

### 中文完整翻譯

一名 analyst 正在檢查多個系統中的事件，但很難將不同資料點進行關聯。下列哪一項最可能是系統存在的問題？

A. 存取權限  
B. 網路分段  
C. 時間同步  
D. 無效的 playbook

---

### 答案與解析

**正確答案：C. Time synchronization**

#### 為什麼正確

事件關聯最重要的共同欄位之一，就是 timestamp。

假設三台設備實際事件順序是：

```text
10:00:00 phishing click
10:00:04 PowerShell execution
10:00:08 outbound C2
```

但三台 host clock 分別差：

```text
Host A: +0 sec
Host B: -7 min
Firewall: +3 min
```

SIEM (Security Information and Event Management，安全資訊與事件管理) 中看到的 timeline 就會完全錯亂。

分析師可能因此錯判：

- C2 比 execution 更早
- user login 發生在 process creation 後
- containment 看似發生在 compromise 前
- authentication event 無法與 endpoint event 對齊

所以 NTP (Network Time Protocol，網路時間協定) 或其他可靠 time synchronization 是 log correlation 的基礎。

#### 其他選項為什麼不對

**A. Access rights**  
權限不足可能讓 analyst 看不到某些 log，但題目強調的是「已有多系統 event，卻難以 correlate」，時間不一致更直接。

**B. Network segmentation**  
Segmentation 影響 connectivity 與 security boundary，但不會直接讓既有 event timestamp 難以對齊。

**D. Invalid playbook**  
Playbook 影響 response workflow，不是跨系統 telemetry correlation 的根本條件。

#### 背後需要掌握的 CySA / 實務概念

Log timestamp 其實還有更多坑：

- UTC (Coordinated Universal Time，協調世界時) vs local time
- daylight saving time
- timezone offset
- clock drift
- ingest time vs event time
- delayed log forwarding
- device reboot
- virtualization clock issue

好的 investigation 通常會區分：

**event timestamp**：事件真正發生時間。  
**ingestion timestamp**：SIEM 收到 event 的時間。

兩者可能差幾秒，也可能差幾十分鐘。

#### SOC / IR 記憶點

**Timeline analysis 的第一個問題不是「哪條 log 最重要」，而是「這些 clock 能不能互相信任」。**
